# Задание 1. Анализ и планирование

### 1. Описание функциональности монолитного приложения

**Управление отоплением:**

- Пользователи могут удалённо:

    - включать/выключать отопление в своих домах

- Система поддерживает:

    - добавление датчика температуры
    - обновление параметров датчика температуры
    - удаление датчика температуры

**Мониторинг температуры:**

- Пользователи могут:

    - получать информацию о показателях всех датчиков температуры

- Система поддерживает:

    - получение показателей с датчиков температуры по запросу

### 2. Анализ архитектуры монолитного приложения

- Язык: Go v1.22
- Фреймворк: Gin v1.8.2
- БД: PostgreSQL v16
- Внешние интеграции: с сервисом temperature-api по HTTP
- Архитектура: монолит (содержит все компоненты системы: слой работы с данными, сервисный слой, модели, REST API)
- Взаимодействие: синхронное с БД и внешним API
- Масштабируемость: ограничена масштабируемостью всего монолита
- Развёртывание: требует остановки всего приложения

### 3. Определение доменов и границы контекстов

Домен: умный дом

- поддомен: управление пользователями

    - контекст: регистрация пользователя
    - контекст: авторизация пользователя
    - контекст: проверка токена

- поддомен: управление устройствами

    - контекст: регистрация, обновление и удаление устройства
    - контекст: получение состояния устройства
    - контекст: локация устройства
    - контекст: объединение устройств в группы (модули)

- поддомен: сценарии работы с устройствами

    - контекст: сценарий автоматизации
    - контекст: триггер выполнения команды
    - контекст: условия выполнения команды
    - контекст: действие
    - контекст: результат выполнения команды
    - контекст: журнал выполнения команд

- поддомен: мониторинг устройств

    - контекст: телеметрия
    - контекст: показания датчиков
    - контекст: получение измерений

### **4. Проблемы монолитного решения**

- проблемы текущей реализации:

    - отсутствие интерфейсов, что не позволит легко и быстро добавить реализацию для других типов датчиков даже в
      монолитном решении
    - при запросе информации о всех датчиках их показатели каждый раз на каждый запрос собираются заново и при этом сбор
      выполняется последовательно для каждого датчика
    - отсутствие покрытия тестами, что усложняет рефакторинг текущего монолита и/или выделение микросервисов
    - текущее обновление датчика позволяет среди прочего менять его тип и единицы измерения, при этом сам тип датчика не
      является строго типизированным (можно записать любое строковое значение)
    - развёртывание требует остановки всего приложения, поэтому не происходит бесшовно для конечного пользователя

- проблемы безопасности:

    - отсутствует авторизация пользователей, т.е. доступ к системе получает любой желающий
    - пользователь может просматривать показатели чужих датчиков

- гипотетические проблемы:

    - синхронное обращение к БД и внешнему API

      При условии, что в системе пока только 100 модулей управления, на текущий момент это может не быть проблемой. Но
      нужно так же учитывать частоту сбора показателей модулей, рост кол-ва модулей в перспективе, а так же специфику
      взаимодействия с модулями (задержки по сети, ожидание команд подтверждения и т.п.).

    - масштабируемость, устойчивость к отказам

      В будущем, в случае появления более нагруженных частей приложения, их нельзя будет независимо масштабировать.

# **Задание 6. Разработка MVP**

Реализована простейшая логика для двух микросервисов:

1. [device-service](apps/device-service)
2. [telemetry-service](apps/telemetry-service)

В [docker-compose.yml](apps/docker-compose.yml) настроена интеграция с монолитом:

- монолит получает в качестве переменных окружения ссылки на сервисы
- в самом монолите в комментариях описано, где должны быть заменены запросы на запросы к новым сервисам

После полного перехода монолит останется в роли API Gateway: будет маршрутизировать запросы от веб-интерфейса к
сервисам, в т.ч. проверять права доступа пользователей через user-service и давать или не давать разрешение на доступ к
информации от других сервисов.
